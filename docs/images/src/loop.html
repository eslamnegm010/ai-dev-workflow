The task loop

Every substantive task runs through the same six steps

01
Plan file
docs/plans/<step>.md. Every decision made, tests mapped to acceptance criteria.
main session
02
Implement
Fresh agent builds exactly the plan, commits locally, never pushes.
implementer agent
03
Quality gate
Whole repo green: analyze, format, guards, tests, goldens. Re-run by the main session.
run-gate.sh
04
Review
Reads only the pushed diff. Never saw the plan. Posts one review.
reviewer agent
05
Status files
Progress log, RESUME HERE, matrix row, decisions. Same branch.
main session
06
Merge
Gate green on the final commit, squash merge, branch deleted.
main session
Must fix? Back to the implementer. One fix round is normal; a second failed round and the main session takes the task over.
Small task?Docs, copy, config: the main session edits directly, runs the gate and self-reviews.
Missing spec?Logged as a discrepancy with options and a recommendation. Never guessed.
Failing test?Find whether the code or the test is wrong. Never edit a test just to pass.
